# 0016 — 복합 DH 타석의 네이버 포지션 재검증

**상태: 채택**

## 맥락

[0015](0015-position-exposure-adjustment.md)의 VB 복합 DH 표기는 전환 시점을 알 수 없어 범위로 처리했다. 사용자가 네이버 타석별 포지션으로 재검증하도록 요청했다. 실제 문자중계에는 최종 라인업과 별개로 타석 시작 당시의 `batterRecord.pos`가 있다.

## 결정

[검증 방식과 결과](../../analysis/leaderboards/position-adjustment.md)에 따라 복합 DH 타석만 네이버와 대조한다. ID·이름·이닝·초/말·같은 선수의 타석 수를 확인해 순서로 연결한다. 첫 투구·타석 결과 전에 같은 포지션의 소개가 반복되는 경우 한 타석으로 취급한다. 확인할 수 없는 기록은 기존 범위로 유지한다.

검증 모듈과 입력 스냅샷을 별도로 두고 얼린 parser·naver 모듈은 변경하지 않는다. VB 입력 해시가 달라지면 검증을 무효화하며 일일 수집 이후 재검증한다. 확정된 이닝은 캐시하고 미확정·신규 이닝은 다시 조회한다. 수동 강제 재조회도 지원한다.

## 기각한 대안

- 경기 최종 라인업의 위치를 모든 타석에 적용: DH→수비 전환 시점을 잃는다.
- 이닝 시작 문구를 타석으로 집계: 타자 소개와 중복된다.
- 타석 수가 다른 그룹을 임의로 순서 연결: 누락된 타석 때문에 뒤 타석까지 잘못 배정될 수 있다.

## 결과

2026-10-06 기준 기존 미확정 128타석은 DH 116·수비 12로 모두 해소됐다. 이후 누락이 생기면 범위로 돌아간다. 순수 DH와 대타·대주 전체의 네이버 검증으로 범위를 확대했다고 주장하지 않는다. 반복 타석·역할 전환·중복 소개·누락·신원 불일치·입력 변경 감지를 테스트한다.
