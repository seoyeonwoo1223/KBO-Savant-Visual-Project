# 0021. Conditional Finder의 투구 단위 검색과 날짜별 정적 파일

- **상태**: 채택

## 맥락

구종·구속·카운트·투구 판정·타격 결과를 기억하는 사용자가 해당 경기와 타석을 찾아 티빙에서 영상을 확인하려고 한다. GitHub Pages는 서버 검색을 제공하지 않으며 기존 프로필은 집계 결과여서 개별 공을 복원할 수 없다.

## 결정

- canonical games/events/pitches에서 2022–2026 개별 투구 검색 파일을 생성한다. 날짜별 파일은 타석 정보를 한 번만 저장하고 투구는 열 목록과 배열로 저장한다. 선수별 날짜 목록과 기간으로 파일을 줄이고 최대 6개 요청을 동시에 보낸다.
- 같은 항목의 선택은 OR, 서로 다른 항목은 AND다. Take/Swing은 원자료 플래그를 따르며 미분류 투구·타석 결과를 임의로 스윙·아웃으로 치환하지 않는다.
- 타석 결과 조건의 기본값은 마지막 투구다. 전체 타석 옵션을 켜도 구종·구속·카운트·판정·선수 조건은 각 공에 적용한다. 상세에는 해당 타석의 모든 투구와 교체 선수를 보존한다.
- 카운트는 투구 전 값이다. 이닝 내 타석 순서는 투구 없는 타석도 events에서 포함한다. 없는 구속·카운트는 0이 아니며 해당 값으로 필터링할 때 제외한다.
- 검색 실패 시 일부 날짜의 성공 결과를 전체 결과로 내보내지 않는다. 모든 필요한 파일이 성공해야 결과를 표시한다.
- 영상 연결은 장면 정보 복사와 티빙 홈 열기다. 확인된 경기 URL·영상 시각 대응 데이터가 생기면 확장한다.

## 기각한 대안

- 기존 웹 프로필 JSON 재사용: 집계 결과이고 개별 공·경기 식별자가 없어 검색 근거가 되지 않는다.
- 시즌 전체를 최초 접속 때 받기: 선수·기간 검색에도 불필요한 다운로드와 메모리가 든다.
- 투수·타자별로 전체 투구를 각각 내보내기: 같은 공을 중복 저장하고 타석 전체 조회에 상대 선수 데이터를 추가로 받아야 한다.
- 경기 시작 시각으로 영상 재생 시점을 계산하기: 중계 준비·편집·광고 시간을 모르므로 정확성을 보장할 수 없다.

## 결과

`conditional_finder.py`, CLI `--only conditional_finder`, metric_state 및 일일 workflow가 검색 데이터를 갱신한다. Python·Node 테스트와 `scripts/check_conditional_finder.py`가 타석 종료/전체 타석, 원자료 경기 대조, 페이지·공유·실패 복구와 화면 규격을 확인한다. 새 앱의 첫 로컬 검토와 배포를 위해 최초 날짜별 검색 데이터·썸네일도 생성한다.
