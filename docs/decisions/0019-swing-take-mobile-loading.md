# 0019. 모바일 Swing/Take는 로딩 표시에서 완성된 이미지로 전환

- **상태**: 채택 (2026-10)

## 맥락
모바일 이미지가 생성되는 동안 기존 반응형 DOM이 먼저 보였다가 한 장짜리 프로필로 바뀌었습니다. CDN·데이터·iframe 캡처가 느리면 이 중간 화면이 더 오래 노출됐습니다.

## 결정
- 모바일 선수 프로필은 `<head>`에서 `profile-loading` 상태를 설정해 본문이 처음 그려지기 전부터 프로필 영역을 가립니다. 검색 화면·데스크톱·썸네일은 제외합니다.
- 프로필 영역 밖에 접근 가능한 `role="status"` 로딩 문구를 표시합니다. 숨긴 영역은 데스크톱 iframe 캡처 대상에 영향을 주지 않습니다.
- 데이터 → 캡처 → PNG blob → 이미지 `decode()`가 끝난 후 `profile-imaged` 상태로 바꾸고 로딩 표시를 해제합니다.
- 데이터 실패 시 기존 오류 안내를 보이고, 캡처·blob·decode 실패 또는 라이브러리 누락 시 기존 DOM fallback을 표시합니다. 화면 폭이 바뀌면 오래된 비동기 결과가 새 상태를 덮어쓰지 못하게 기존 토큰을 유지합니다.

## 기각한 대안
- DOM을 잠깐 보여 준 뒤 숨기기: CDN이나 데이터 로딩 전부터 발생하는 첫 화면 노출을 막지 못합니다.
- 이미지 src를 지정하자마자 로딩 해제: 아직 디코딩되지 않은 빈 이미지가 보일 수 있습니다.
- fallback 제거: 캡처를 사용할 수 없는 환경에서 프로필을 볼 수 없게 됩니다.

## 결과
- 중간 반응형 화면 없이 로딩 표시 → 완성된 이미지로 전환합니다. [0004](0004-swing-take-mobile-image.md)의 모바일 이미지·fallback 방식은 유지합니다.
- `tests/test_swing_take_loading.cjs`가 초기 상태·디코딩 대기·실패 fallback·화면 폭 전환을 검사합니다. 브라우저에서는 CDN·데이터·캡처를 각각 지연시켜 중간 DOM 노출이 없는지 확인합니다.
