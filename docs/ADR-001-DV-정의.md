# ADR-001 — Decision Value 베이스라인 정의

- **상태**: 채택 (결정만 확정, 구현 미착수)
- **일자**: 2026-09-13
- **맥락 문서**: `docs/HANDOFF-타석판단지표.md` §4 Task 1, §3.1 C-6 / C-9
- **적용 범위**: `visualbaseball.zone_decision`의 DV 계열 (`raw_dv`, `dv_per_100`, `dv_plus`)

## 결정

DV의 베이스라인을 **리그 평균 정책**으로 확정한다.

```
DV_avg = (S − p) · Δ            S ∈ {0,1} 스윙 여부, p = P(스윙 | 상황), Δ = V_swing − V_take
```

현재 구현(`zone_decision.decision_value`, 101–103행)은 `(2S−1)·Δ` **원형**이며 이것을
`DV_avg`로 교체한다. 기존 `(2S−1)·Δ`는 폐기하고 별도 이름으로도 남기지 않는다.

결과 기반 `decision_run`(`swing_take.py`)은 이 결정의 대상이 아니다. 이미
`observed_decision_run` · "Run Value"로 라벨이 분리되어 있고(C-6) 그대로 둔다.

**구현은 Task 2(Δ 표면) 이후에 한다.** 이 ADR은 정의만 고정한다. 지금 산식을 바꾸면
교체될 Δ 표면 위에서 계산된 값이 웹에 배포되고, §6의 "시각화·앱 통합은 Task 6 통과 후"를
어긴다.

## 근거

### 1. 세 후보는 같은 판단 신호에 서로 다른 상수항을 더한 것이다

```
DV_raw = (2S−1)·Δ = 2·(S−p)Δ + (2p−1)Δ
DV_avg = (S−p)·Δ  = 1·(S−p)Δ + 0
DV_opt = S·Δ − max(Δ,0) = 1·(S−p)Δ + [p·Δ − max(Δ,0)]
```

셋 다 `c·(S−p)Δ + g` 꼴이고, `g`는 **타자의 선택 `S`에 전혀 의존하지 않는다.** `g`는
"어떤 공을 던져 받았는가"만으로 정해지는 양이다. 선수별 평균을 낼 때 `g`는 지워지지 않고
그대로 남아 판단 지표에 섞인다. 세 후보 중 `g = 0`인 것은 `DV_avg` 하나뿐이다.

### 2. 현재 DV는 절반 가까이가 기회 항이다 (2026 실측)

2026 시즌 300구 이상 163명, 현 ZA v7 표면(`data/metrics/zone_awareness/2026/pitches.parquet`)
기준. 선수 간 분산을 판단 성분 `c·(S−p)Δ` 와 기회 성분 `g` 로 분해한 결과:

| 변형 | 100구당 평균 | 표준편차 | 선수 간 분산 중 기회 성분 지분 |
|---|---:|---:|---:|
| `DV_raw` (현행) | **+6.0288** | 0.9346 | **43.0%** |
| `DV_avg` | −0.1134 | 0.3529 | **0.0%** |
| `DV_opt` | −2.8076 | 0.3947 | 20.1% |

현행 DV의 100구당 +6.03이라는 수준 자체가 판단 능력이 아니라 `|Δ|` 항이다
(`(2S−1)Δ = 2·DV_opt + |Δ|`, 브리프 §2.4). 리그 상대 지표인 `dv_plus`는 이 **수준**만
제거하고 **선수 간 분산**은 제거하지 못하므로, DV+ 역시 43%가 기회 항이다.

기회 성분과의 선수별 Spearman: `DV_raw` 0.648, `DV_opt` 0.009, `DV_avg` 0.163.
변형 간 순위 상관은 `DV_raw`↔`DV_avg` 0.834 — 무시할 수 있는 차이가 아니다.

Δ 표면이 Task 2에서 교체되면 위 수치는 달라지지만, **`g = 0`은 대수적 성질이라 어떤
표면에서도 유지된다.** 표에 의존하는 것은 지분의 크기뿐이다.

### 3. 저장소의 기존 지표군과 같은 형태다

```
swing_aggression = 100 · mean(S − p)
za_raw           = 100 · mean((S − p) · (2·p_zone − 1))
DV_avg           = 100 · mean((S − p) · Δ)
```

셋 다 동일한 스윙 잔차 `(S − p)`에 가중치만 달리 준다 — SA는 1, ZA는 존 확실성,
DV는 런 가치. `(2S−1)Δ`만 이 형태 밖에 있었다. `DV_avg` 채택으로 세 지표가 한 계열이
되고, 세 층 분리(§1)의 전제도 지표 형태 수준에서 일관해진다.

### 4. `DV_opt`를 택하지 않은 이유

`DV_opt ≤ 0`이라는 "완벽한 선택 대비 잃은 런" 해석은 명료하다. 그러나 기회 항 지분이
20.1%로 0이 아니고, 그 항 `p·Δ − max(Δ,0)`은 리그 평균 스윙률 `p`를 통해 **타자가 아니라
리그가 그 공을 어떻게 대하는가**를 실어 나른다. 해석의 명료함이 오염을 상쇄하지 않는다.

Task 4에서 `DV_opt`를 **보조 열**로 함께 출력할지는 열어 둔다. 그 판단은 Task 4에서
하고, 헤드라인 DV는 `DV_avg`로 고정한다.

## 결과

- `zone_decision.decision_value()`의 산식이 Task 2 이후 `(S − p)·Δ`로 바뀐다.
  `p`는 이미 `pred['p']`로 존재하므로 새 모델 입력은 필요 없다.
- `CONTRACT['raw_dv']` 문구 — 현재 `'sum(V_swing - V_take for swings; sign reversed for
  takes)'` — 를 함께 고쳐야 한다. 계약 문자열과 산식이 어긋나면 웹이 잘못된 정의를 노출한다.
- DV 값의 스케일과 부호 분포가 바뀐다(평균 +6.03 → ≈0). `dv_plus`의 100/15 정규화는
  구조가 그대로이므로 페이지 레이아웃 변경은 필요 없다.
- 과거 시즌 산출물은 재생성 대상이다. `metric_state`가 코드 해시로 판정하므로 자동으로
  걸린다.

## 확인해야 할 것 (Task 4)

`DV_avg`의 리그 평균 0은 `p`가 교정되어 있을 때만 성립한다. 2026 실측 평균은 300구 이상
표본에서 −0.1134/100구로 정확히 0이 아니다 — 자격 표본이 리그 전체가 아닌 점과 교정
잔차가 섞여 있다. Task 4에서 **전체 투구 기준 평균이 0에 충분히 가까운지** 확인하고,
벗어나면 그 크기를 공개할 것. 0으로 맞추려고 사후 중심화하지 말 것.
