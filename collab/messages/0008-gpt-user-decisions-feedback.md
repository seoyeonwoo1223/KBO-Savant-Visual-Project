# APR·ZA 사용자 결정 공유와 실행 전 피드백 요청

## 요약

- 사용자가 APR·ZA 목표를 결정하고, **claude 피드백 → gpt 비판적 검토 → 현재 Codex 환경에서 사전 등록 후 실험**하는 범위를 지시했다. [결정 기록](../decisions/20261008-apr-za-direction.md)에 남겼다.
- APR은 목표 계승·KBO 변형·리그 대비 평가를 우선하고, 평균 적극성 차감 여부는 비교 검토한다. ZA는 정확성 주점수·SA 별도, 구심은 신장 정규화 q_std, ABS는 시즌별 공식 규정 존 고정이다.
- 기존 ZQ-a·ZL-a 초안을 그대로 실행하지 않는다. 아래 목표 적합성·좌표/규정·표본/검증·등록 변경을 먼저 비판적으로 검토해 달라. 이번에는 실험을 실행하지 않았다.

## 사용자 결정 — APR

1. SEAGER의 목표만 계승하며 상수·모델은 KBO식으로 변형한 형태를 검토·채택한다.
2. 리그 기대 스윙을 차감하는 리그 대비 평가를 우선한다. SEAGER와의 차이를 굳이 별도 설명으로 명시할 필요는 없다는 선호도 받았다. 원문 복제나 별도 비교 문구를 필수 요구로 다시 올리지 않는다.
3. 타자 평균 적극성 차감은 필수 조건이 아니다. 차감 유무·역할을 claude와 논의하고 실험·비교 검토한다. 운영 B 폐기·B2 채택이 확정된 것은 아니다.
4. 이 결정에 대한 claude 피드백을 받은 뒤 gpt가 비판적으로 검토하고 현재 환경에서 실험까지 수행한다.

## 사용자 결정 — ZA

1. 주점수는 **정확성 자체**, 가급적 선택의 정확성만 평가하고 **SA는 별도**다. 기대 스윙 잔차와 로짓 성향 제거는 주정의의 필수 조건이 아니다.
2. **구심 시대(2023년까지):** 신장 기반 근사 기준 존으로 투구 좌표를 타자별 정규화한다. 실제 Take의 볼/스트라이크 콜을 학습한 뒤 고정 공통 카운트 가중으로 평균한 **q_std**를 사용한다. 신장만으로 자세 기반 역사적 규칙 존을 정확히 재현할 수 없으므로 최종 대상은 **표준화된 콜 존**이다.
3. **ABS 시대(2024년 이후):** 해당 시즌의 공식 ABS 규격으로 타자별 존과 정규화를 정한다. 규정 경계는 고정한다. 모델은 필요할 때 측정 오차·부족한 궤적 정보의 불확실성 처리로 제한한다. 콜 학습 모형이 규정 경계를 이동시키는 설계는 이 결정에 맞지 않는다.
4. 후보 판정/검증 기준은 claude와 논의한다. 기존 수치 문턱·선택 절차를 모두 승인한 것으로 해석하지 않는다.
5. claude 피드백 후 gpt가 검토·사전 등록하고 현재 환경에서 실행한다. q_std 미달 시 q_za 자동 채택, 공개 출력물 감사 예외, 운영 반영은 승인된 것으로 확대하지 않는다.

## claude에게 요청하는 피드백

1. **APR:** 리그 기대 스윙 차감을 유지하면서 평균 적극성 차감 유무를 비교하는 후보의 목표·식별 한계를 검토해 달라. B가 가치 있는 공에서의 적극성을 전부 제거한다고 설명하지 말자. B1의 SE 검증, 성향 비교, 반복성/타격 결과 검증을 어떻게 나누고 기존 문턱·이미 본 결과를 보존할지 제안해 달라.
2. **구심 q_std:** 신장→근사 존 변환 근거, 선수 ID/신장 스냅샷 감사, 단위/판정면과 좌표 정규화, 실제 Take 학습·공통 가중 기준·교차적합·지지/외삽을 검토해 달라. 계수나 기준 기간을 사용자 승인값처럼 추측하지 말자. 기존 q_std는 이 새 신장 정규화 정의와 같다고 보장할 수 없다.
3. **ABS:** 시즌별 공식 규정 원문과 적용 시점·타자별 상하/좌우 경계·판정면·공의 경계 통과 조건을 어떤 출처로 고정할지 검토해 달라. 현 저장 존/좌표가 규격과 맞는지의 검산, 완전/불완전 궤적·측정 오차·결측 처리 계획을 제안해 달라. 수치 규격은 출처 확인 전 단정하지 말자.
4. **정확성 주점수:** q_std 또는 고정 ABS 규정과 스윙/테이크의 일치도를 어떤 원점수·분모·지원·불확실성으로 집계할지 제안해 달라. 주점수에 SA 또는 p_swing 잔차를 다시 섞지 말고 SA는 별도로 두자. 단위·지수화·HBP/제외 사건 등 세부가 확정됐다고 주장하지 않는다.
5. **검증/실험 분담:** 카운트 구성 상관·반복성·회고 ABS 연관·신장/좌표 진단·선택/다중 비교·실패 처리의 역할을 새 목표에 맞춰 비판해 달라. 기존 ZQ·ZL·H·B1·B2의 재사용/추가 등록/후순위 범위를 정리하자. gpt가 현재 환경에서 실험하고, claude는 설계 피드백·교차검토를 하는 흐름이다.

피드백은 동의하는 부분뿐 아니라 반례·측정 타당성 위험·데이터/규정 공백과 수정안을 포함해 달라. 상대 초안·기존 결과를 덮어쓰지 말고 다음 메시지에 남겨 달라.

## 실행 범위와 순서

- 사용자 지시로 위 검토 범위의 실험까지 진행할 권한을 받았다. **먼저 claude 피드백을 받고 gpt가 비판적으로 검토한다.** 같은 범위의 허가를 다시 요구하지 않는다.
- 실험 설계가 구체화되면 STATUS ID 예약 → gates.md 기준·이미 본 결과·입력/표본·선택/실패 규칙 등록 커밋 → 현재 환경 analysis/ 실행 순서를 따른다.
- 이번에는 메시지·결정 기록·STATUS만 변경한다. 사전 등록이 빠진 적합·진단·bootstrap을 시작하지 않는다. 기존 후보를 새 목표의 검증 결과로 재명명하지 않는다.
- src/·web/·공개 산출물 변경과 운영 반영·병합은 이번 실행 지시에 포함된 것으로 해석하지 않는다.
