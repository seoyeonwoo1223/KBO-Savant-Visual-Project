# 공동 규칙

두 에이전트(claude, gpt)가 똑같이 따릅니다. 저장소 전체 규칙은 [AGENTS.md](../AGENTS.md)와 `docs/`에 있고, 여기에는 그 위에 더하는 것만 둡니다. 충돌하면 사용자의 지시가 우선합니다. 이 파일은 사용자 승인을 받고서만 고칩니다.

## 1. 사용자 고정 규칙

| 항목 | 규칙 |
|---|---|
| 변경 범위 | 실험은 `analysis/`에서만 합니다. `src/`, `web/`, 공개 산출물(`data/metrics`, `web/data`, `exports`)은 사용자 승인 후에만 바꿉니다 |
| 실험 등록 | 실험마다 채택 기준을 `analysis/sbj_formula/gates.md`에 **먼저 등록·커밋하고** 실행합니다. 결과를 본 뒤 기준을 바꾸지 않습니다. 별도 사전 등록 파일은 부록으로만 쓰고, 판정 기준은 반드시 gates.md에 둡니다 |
| 이미 본 결과 | 등록 전에 본 수치가 있으면 등록 절에 "이미 본 결과"로 밝힙니다 |
| 데이터 읽기 | `data/curated/summary.json` → `schema.json` → 필요한 행만 읽습니다 |
| 모델명 | 커밋 메시지, PR, 코드 주석에 모델명·모델 버전을 쓰지 않습니다. 창구 문서의 보낸이 이름(claude, gpt)은 역할 표기로 씁니다 |
| 커밋 | 작성자를 `github-actions[bot]`으로 남기지 않습니다. 커밋 제목은 `영역: 무엇을 했는지` |
| 프로세스 종료 | PID로 끝냅니다. `pkill -f`는 쓰지 않습니다 |
| 예약·구독 | 예약 점검, 모니터링, PR 구독을 하지 않습니다. PR이 자동 구독되면 즉시 해제합니다 |
| 병합 | 사용자가 "병합해줘"라고 할 때만 합니다. PR은 draft로 엽니다 |
| 언어 | 답변, 문서, UI는 한국어입니다 |
| 외부 데이터 | 외부 ZJ 데이터는 저장소에 커밋하지 않습니다 |
| 재현 환경 | Python 3.12, `pip install -r requirements.txt -c constraints-za.txt`, `PYTHONPATH=src`, `OMP_NUM_THREADS=2` |

**산식 채택 절차** (운영 반영은 사용자 결정 후):

1. `MODEL_VERSION`을 올립니다.
2. 2019–2026을 재빌드합니다. 2026을 먼저 검증한 뒤 나머지 시즌을 돕니다.
3. 시즌마다 `metric_state.mark_built`를 실행합니다.
4. `scripts/check_zone_decision_outputs.py`를 돌립니다.
5. 선수 변동표를 만듭니다.
6. 페이지 방법론을 고치고, JS·CSS를 바꿨다면 캐시 버스터를 올립니다.
7. pytest와 `.cjs` 테스트를 돌립니다.

## 2. 창구 규칙 (어긋남 방지)

| # | 규칙 | 막으려는 사례 |
|---|---|---|
| R1 | **기준 동기화.** 작업 전에 `git fetch origin master collab/claude-gpt`를 하고 `python collab/check.py`를 통과시킵니다. 메시지 머리말에 읽은 master SHA와 MODEL_VERSION을 적습니다. MODEL_VERSION이 origin/master와 다르면 작업하지 말고 먼저 알립니다 | za7.8이 운영 중인데 za7.7(APR A) 체크아웃으로 검토 |
| R2 | **푸시된 것만 인용.** 브랜치와 커밋은 원격에 있어야 하고 전체 40자 SHA로 씁니다. 아직 안 올린 것은 인용하지 않습니다 | 원격에 없던 `review/apr-za-20261003`·`ca8de0fd` |
| R3 | **숫자에는 정의와 재현 경로.** 대상(시즌·표본·구간), 통계량, 스크립트 `경로@SHA`, 출력 파일을 함께 적습니다. 재현 경로가 없는 숫자는 "참고치"로 표시합니다 | 재현되지 않은 "수축 제거 시 5.7점" |
| R4 | **실험 ID는 먼저 예약.** STATUS.md 레지스트리에 ID를 올리고 메시지로 알린 뒤, gates.md에 등록 커밋을 하고, 그다음 실행합니다 | X-b와 B1/B2 중복 초안, Z-e 이름 중복 |
| R5 | **상대 산출물은 고치지 않음.** 반론은 새 파일·새 메시지로 합니다. 상대 브랜치에는 새 파일 추가와 gates.md 새 절 추가만 합니다. force push 금지. 푸시가 거절되면 fetch 후 자기 미푸시 커밋만 rebase합니다 | |
| R6 | **판정 어휘 통일.** 주장마다 `동의 / 부분 동의 / 반대 / 판정 불가` 중 하나와 근거(`파일:줄@SHA` 또는 재현 명령)를 붙입니다 | 판정 없이 요약만 오가는 문제 |
| R7 | **결정은 사용자만.** 채택, 병합, 운영 반영, 측정 정의 변경은 STATUS.md "사용자 결정 대기"에 올립니다. 두 에이전트가 합의해도 결정이 아닙니다 | |
| R8 | **메시지는 추가만.** 보낸 메시지는 고치지 않고, 정정은 새 메시지로 합니다. STATUS.md는 둘 다 고칠 수 있고, 고친 행을 메시지에 적습니다 | |
| R9 | **차례 표시.** 메시지 끝에 `## 다음 차례`와 사용자가 상대에게 전할 한 줄을 씁니다 | 누가 다음에 무엇을 하는지 불명확 |
