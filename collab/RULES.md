# eAA 공동 규칙

APR/ZA 창구의 R1–R9를 같은 목적에 맞게 적용한다. eAA의 실험 등록 경로와 운영 JSON 검사는 이 채널에 맞춰 분리한다. APR/ZA의 규칙·gates·메시지는 고치지 않는다. 사용자 지시가 이 규칙보다 우선한다.

2026-10-09 추가 승인: 원격 인계 검증, 원래 tracking 코드 부재 시 계산 전 산식을 선언한 별도 재생성, 코드·선택 입력·결과·근거 및 창구 게시. EAA-TR1은 `analysis/arm_angle/tracking_rebuilt_20261009/gates.md`에 등록한다. 기존 등록 경로/과거 gates를 보존한다. 운영 변경·병합은 승인 범위에 포함하지 않는다.

- R1 기준 동기화: master·창구·연구 브랜치를 fetch하고 `check.py`를 통과시킨다. 운영 model_id와 모델 파일 SHA가 현재 master와 같아야 한다. 예전 캐시의 마감과 최신 master의 마감을 구분한다.
- R2 원격 인용: `브랜치@전체40자SHA`만 인용한다. 자료가 로컬에만 있으면 그 상태를 명시하고 상대가 확보했다고 가정하지 않는다.
- R3 수치 정의: 모집단·시즌/월·분모·단위·평균오차/MAE/음의오차량·재현 코드와 출력 경로를 함께 남긴다. 미확인은0이 아니다.
- R4 실행 전 등록: ID를 STATUS에 등록하고 연구 브랜치의 ID별 등록 파일에 기준을 먼저 커밋한 뒤 실행한다. `check.py`의 `GATES`가 경로 목록을 정한다. EAA-SI1·SUP1·CL1의 역사적 등록은 `analysis/arm_angle/sinker_anchor_20261007/gates.md`를 유지하고, 후속 EAA-CL*은 `analysis/arm_angle/claude_review_20261007/gates.md`를 사용한다. 다른 ID는 실행 전에 별도 경로를 목록에 추가한다. 이미 본 결과를 밝힌다. 소급 변경 금지.
- R5 상대 보존: 상대 산출물을 수정하지 않는다. 반론·정정은 새 파일·새 메시지다. force push 금지.
- R6 판정: 주장마다 동의/부분 동의/반대/판정 불가와 근거를 붙인다. 모델 재현과 새 확증은 다르다.
- R7 사용자 결정: 운영 반영·측정 정의 변경·병합은 사용자 결정이다. 이번 승인 범위는 싱커 앵커와 표본 지원값 연구 및 창구 개설이다.
- R8 추가만: 보낸 메시지는 고치지 않는다. STATUS는 공동 갱신하고 변경한 행을 새 메시지에 적는다.
- R9 차례: 메시지 끝에 다음 차례와 사용자 전달 한 줄을 적는다. 상대 응답을 대신 작성하지 않는다.

연구는 `analysis/`에서만 한다. `src/`, `web/`, `data/`와 공개 범위·고정 모델·과거 연구 조건은 바꾸지 않는다. KBO 참고각도를 학습 정답으로 쓰지 않는다. 이미지 전수·실제 암슬롯·Y2Y 측정·미확보 전체 원본 확인 주장을 하지 않는다. 2024 및 2025년5·6·7·8·9월은 재사용이다. 싱커를 우선하고 포심을 유지하며 커터 주구종에 새 연구 경로를 만들지 않는다. 역사의 실패 자료는 보존한다.

커밋·문서·UI는 한국어로 쓴다. 발신/수신 이름은 역할 표시이고 분석자의 모델명·서명·버전은 코드·커밋에 넣지 않는다. 운영 모형의 `eAA-v3`는 재현 식별자다. 작성자를 자동화 봇으로 남기지 않는다. 예약·모니터링·PR 구독은 설정하지 않고 PR은 draft로 둔다.
