# p_swing 입력 비교 (za7.2)

SBJ(ZA) `100 * mean((S - p_swing) * (2*p_zone - 1))`의 `p_swing` 입력을 정한 비교다. `p_zone`(ABS 판정면)과 사건·가치 모델(DV)은 그대로 두고 p_swing만 바꿨다. 구속·구종·무브먼트는 심판 판정이 아니라 리그 타자의 스윙 선택을 설명하는 입력으로 본다.

## 결론

| 입력 | 판정 | 근거 |
|---|---|---|
| 투수 손 | **채택** (za7.2) | 세 시즌 모두 네 조건 통과 |
| 같은 손/반대 손 상호작용 | 제외 | 세 시즌 모두 1·2번 조건 미달. 투수 손과 타자 손이 각각 범주 입력이므로 트리가 필요한 만큼은 학습한다 |
| 무브먼트 (현행 보정 HB·IVB) | **현행 유지, 문제 미해결** | 아래 설명 |
| 무브먼트 재추정 보정 (구장×구종, 구장×구종×투수 손) | 제외 | 현행 대비 1·3번 조건 미달, 구장 셀 조건도 세 시즌 모두 미달 |
| 릴리스 좌우 (`release_x_55`) | 제외 | 무브먼트 위에 더하면 이득 없음. 무브먼트 없이 더하면 2024만 통과 |
| 접근각 (VAA·HAA, 앞면 속도 방향) | 제외 | 무브먼트 위에 더하면 세 시즌 통과 없음 |

그래서 이번 공식 p_swing 입력은 **현행 무브먼트 유지 + 투수 손 추가, 궤적 파생값 없음**이다. 궤적 파생값 결론은 시험한 정의에 한정된다. 릴리스 좌우는 55ft 평면 x, 접근각은 앞면 속도 방향으로 정의했다. 다른 정의·조합이나, 무브먼트 보정이 바뀐 뒤의 궤적값까지 포함하는 일반 결론은 아니다.

### 무브먼트

**무브먼트는 검증을 통과해 채택한 입력이 아니라 현행 유지다.**

4번 조건은 구장×구종 셀 잔차 RMS가 무브먼트 없는 모델 대비 +5% 이내여야 한다는 것이다. 이 조건을 넘지 못한 시즌은 보정 방식마다 다르다.

- 현행 보정표: 2024(1.058)·2026(1.062). 2025는 0.976으로 통과.
- 구장×구종 재추정: 세 시즌 모두(1.045/1.060/1.095).
- 구장×구종×투수 손 재추정: 세 시즌 모두(1.048/1.052/1.074).

셀 평균 z²도 무브먼트를 넣으면 오른다. 현행 보정은 1.37→1.59(2024), 1.40→1.65(2026)이다. 무브먼트가 구장×구종 단위의 보정 오차를 남긴다는 뜻이다. 재추정 보정을 투수 손별로 나눠도 이 증가는 사라지지 않았다.

반대로 무브먼트를 빼는 변경도 같은 규칙으로는 채택할 수 없다.

- 날짜 블록 OOF log loss가 0.007–0.009 나빠진다(z 17.8–23.3).
- 타자 hold-out log loss도 0.007–0.008 나빠진다(z 17.8–20.9).
- ECE는 세 시즌 모두 나빠진다.

그래서 현행을 유지하되, 구장 잔차 문제는 해결되지 않은 것으로 남긴다.

**3차 비교(탐색적): TrackMan 검증 보정 무브먼트(`H1M4`).** `analysis/movement_calibration/`의 보정은 TM 기준 구장×구종 무브먼트 편향을 약 7cm에서 0.5–0.7cm로 줄인다. 이 보정을 넣은 결과는 다음과 같다.

예측(1·2)은 현행보다 세 시즌 모두 좋다. 그러나 ECE와 구장 셀 조건에서 미달이라 채택하지 않았다. 무브먼트 측정 편향을 크게 줄였는데도 구장 셀 z²가 남는다(2025 1.73→2.03). 따라서 이 조건의 실패는 무브먼트 측정 편향만으로는 설명되지 않는다.

사후 진단으로 경기 단위 부트스트랩 300회를 돌려 구장 RMS 비의 95% 구간을 구했다. 현행은 [0.968, 1.073]·[0.922, 1.038]·[0.981, 1.079], TM 검증 보정은 [0.957, 1.053]·[0.989, 1.078]·[0.981, 1.075]로, 모두 1을 포함한다. 5% 기준이 잡음보다 좁다는 뜻이다. 기준을 바꿀지는 별도 결정 사항이며, 이 결과로 판정을 사후 변경하지 않았다. 전체 수치는 `pswing_results/round3_report.json`에 있다.

팀별 점수 민감도(2025·2026, 소속팀별 평균)도 계산했다. 무브먼트를 넣은 모델과 뺀 모델의 SJ 차이는 팀 평균 기준 0.17–0.23pp 범위다. 이 차이에는 무브먼트에 담긴 실제 투구 정보의 효과와 측정 편향이 함께 들어 있다. 따라서 **구장 편향의 크기가 아니고, 편향이 무시할 만하다는 근거도 아니다.** 2024는 curated에 `batter_team`이 없어 계산하지 않았다.

## 채택 규칙 (결과를 보기 전에 고정)

특성 묶음 X는 X만 없는 모델을 기준으로, 세 시즌 모두에서 네 조건을 만족할 때 채택한다.

1. 날짜 블록 OOF log loss가 paired SE의 2배보다 크게 낮아진다.
2. 타자 hold-out log loss(타자 단위 3-fold, 보정 없음)가 같은 기준으로 낮아진다.
3. ECE(20 분위 구간)가 0.001보다 크게 나빠지지 않는다.
4. 구장×구종 셀(n≥300) 평균 잔차의 가중 RMS가 5%보다 크게 나빠지지 않는다.

1·2의 SE는 처음에 경기 군집으로만 계산했다. 검토에서 타자 hold-out은 타자 단위로 나눈 평가이므로 타자 군집이 맞다는 지적을 받았다. 그래서 두 SE 중 큰 쪽(덜 유의한 쪽)으로 z를 다시 계산했고, 모든 판정이 그대로였다.

**탐색적 결과**로 구분해 둘 것들이 있다. 사전 고정 이후에 추가한 항목이라 사전 기준의 검정력을 갖지 않는다.

- 무브먼트 재추정의 투수 손별 후보(`H1M3`)와 H1 기반 2차 비교
- 보정 전 OOF log loss
- 셀 평균 z²
- 팀별 점수 민감도
- 3차 비교(TrackMan 검증 보정 무브먼트)와 구장 RMS 비의 부트스트랩 구간

선수 SBJ 순위 상관, 최대 변화, 분할 반쪽 신뢰도는 조건이 아니라 진단이다.

## 재현

```bash
export PYTHONPATH=src OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2
for y in 2024 2025 2026; do python analysis/zone_decision/pswing_input_ablation.py --season $y --out /tmp/pswing; done
python analysis/zone_decision/pswing_input_report.py --out /tmp/pswing
```

전체 후보는 시즌당 약 12분(4코어)이 걸린다. `--candidates H1 H1M0 H1M2 H1M3 H1M0Trel`로 일부만 돌릴 수 있고, 표는 있는 후보끼리만 비교한다. HGB 결과는 스레드 수와 무관하게 같았다(`H1`, 1·2스레드 전 투구 오차 0).

현행 입력 후보 `C0`는 2026 운영 `p_swing`과 전 투구에서 오차 0으로 일치한다. 구현한 운영 경로는 실험 후보 `H1`과 2025 블록 1에서 오차 0으로 일치한다.

후보 이름은 다음과 같다.

- `C0`: 현행.
- `H1` / `H2`: 투수 손 추가 / 투수 손과 상호작용 추가.
- `M0` / `M1` / `M2` / `M3`: 무브먼트 없음 / 현행 보정 / 재추정(구종) / 재추정(구종×손).
- `Trel` / `Tang` / `Tboth`: 릴리스 좌우 / 접근각 / 둘 다.

재추정 오프셋은 각 훈련 블록의 원시 VB 무브먼트만으로 추정한다. 보정표·Pitch Arsenal 값·원본 궤적은 읽기만 한다.
