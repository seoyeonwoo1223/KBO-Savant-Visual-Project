# VB 타석 사건 흐름 검증: 탐지 범위와 오탐 (2019–2026)

김택연–임지열 타석(2025-08-09, `reaudit_2025.md` 3절)과 같은 기록 이상이 다른 타석에도 있는지 전 시즌을 조사했다. 코드는 `pa_flow_audit.py`(흐름 규칙), `pa_flow_strict.py`(카운트를 쓰지 않는 TrackMan 엄격 매칭), `pa_flow_exposure.py`(ZA 입력 노출)다. 수치는 `results/pa_flow_summary.json`, `results/pa_flow_strict_summary.json`, `results/pa_flow_strict_tolerance.json`, `results/pa_flow_za_exposure.json`에 있다. 공개 산식과 산출물, curated 데이터는 바꾸지 않았다. 위치가 불확실한 행을 `px`로 대체하거나 특정 행을 지우는 변경도 하지 않았다.

## 요약

- **김택연 타석과 같은 "행이 더 있는" 오류(타석 분리·중복 행)는 드물고, 2024년부터 몇몇 경기에 몰려 있다.** 2024년 3경기 17타석, 2025년 2경기 4타석(김택연 타석 포함), 2026년 1경기 4타석이다. 2019–2023년은 0이다. 2024년 TrackMan 키 비교에서 SPLIT_SAME 5/5, DUP_CONSEC 3/4, DUP_TRAJ 9/12 키의 VB 투구가 TrackMan보다 많았다(3.1절).
- **TrackMan 대조를 볼·스트라이크 카운트 없이 다시 했다(4절).** 경기·반이닝·투수·타자(대응 ID)·투구 순서·아웃·개별 구속 차(±2.0km/h)를 모두 통과한 모호하지 않은 쌍만 썼다. 시즌 VB 투구의 60–76%가 남는다.
  - 카운트 불일치: 매칭 쌍의 0.81–1.10% (시즌당 1,184–1,781구).
  - VB `B`→TrackMan 스트라이크: VB `B` 전이의 0.85–1.22% (시즌당 437–679구).
  - VB `V`→TrackMan 스트라이크: 69–100구 전부.
  - 기존 순서 연결의 비율(0.84–1.12%, 0.86–1.20%)과 거의 같고, 허용폭을 ±1.5·±3.0km/h로 바꿔도 비율은 0.1%p 안에서 움직인다. 절대 수가 준 것은 분모가 줄어서다.
  - **이전 요약의 "시즌당 1,600–2,100구, 570–790구"는 시즌 전체 수가 아니었다.** 순서 연결로 대조된 약 85% 투구 안에서 센 값이다. 이 표현은 고친다.
- **확인된 것은 "두 기록이 어긋난다"까지다.** TrackMan 다음 카운트가 스트라이크로 변했다는 것만으로 실제 행동(헛스윙·루킹)이나 어느 기록이 틀렸는지는 정해지지 않는다. VB 쪽 오류를 가리키는 간접 근거는 두 가지다.
  - VB 자체 타석 흐름: 해당 B를 스트라이크로 바꿔야 VB 타석이 성립하는 경우가 22–28%다. 반대로 B여야 성립하는 경우는 0–3구다. 나머지 67–71%는 흐름으로 판별할 수 없다.
  - ABS 위치(2024): 이 공의 66%가 존 안이다. TrackMan도 볼로 본 VB `B`는 0.5%만 존 안이다.
- **2024년 d≤0.8 "289/289, 정밀도 100%"를 고친다.** 판정 가능한 공은 VB `B` 337구 중 268구(80%)이고, 268구 모두 TrackMan 카운트가 스트라이크로 변했다(95% 하한 98.6%). 이것은 "VB가 틀린 비율"이 아니라 "TrackMan 카운트 기록과 어긋나는 비율"이다(4.8절).
- **`V`는 파서가 세지 않는 것이 확인된 문제다.** TrackMan은 매칭된 `V`를 모두 스트라이크로 본다. VB 자체 흐름도 `V`를 스트라이크로 셀 때 더 많이 성립한다(2024년 125 대 108타석). `V`가 무슨 행동인지는 모른다.
- **흐름 규칙은 오탐이 작고 누락이 크다.** BB_CONT·END_MISMATCH에 걸린 키는 대부분 실제 카운트 불일치다. 그러나 규칙은 TrackMan 카운트 불일치 키의 25–28%만 잡는다(4.9절, 키 단위).
- **ZA 노출(2024):** 엄격 매칭 카운트 불일치 1,482행(0.67%)과 B→TM 스트라이크 538행이 ZA에 들어간다. ZA 행 중 엄격 매칭된 행은 169,828/222,225이라, 실제 규모는 이보다 크다.
- 원본·curated·공개 산식·공개 값은 바꾸지 않았다. 확인된 것과 가설은 6절에서 나누고, 최소 수정안은 7절에 있다.

## 1. 왜 지금 검증이 이 오류를 통과시키는가

- 파서는 VB 타석마다 볼카운트를 0-0에서 시작한다. VB가 한 타석을 둘로 나누면 뒤 기록의 카운트가 처음부터 다시 센다.
- `state_machine.apply_non_terminal_pitch`는 볼을 3, 스트라이크를 2에서 멈춘다(cap). 네 번째 볼이나 세 번째 스트라이크 뒤에 타석이 이어져도 불가능한 카운트가 생기지 않는다.
- 같은 함수는 `V` 호출 코드를 세지 않는다. 그 뒤 투구는 스트라이크가 하나 부족하다.
- 각 VB 타석의 마지막 행을 종료 투구로 둔다.
- `validation.validate_game`은 카운트 범위, 중복 키, 타석 시작 0-0 등만 본다. 흐름 오류는 모두 이 검사를 통과한다.

## 2. 탐지 규칙

원본 호출 코드로 카운트를 cap 없이 다시 센다. 결과 문구로 종료 방식을 나눈다(2022–2024 curated는 `pa_type`이 비어 있다).

| 규칙 | 뜻 |
|---|---|
| K_CONT | 2스트라이크에서 S/T가 나온 뒤에도 타석이 이어짐 |
| BB_CONT | 3볼에서 B가 나온 뒤에도 타석이 이어짐 |
| X_NONLAST | 인플레이(X) 뒤에도 타석이 이어짐 |
| END_MISMATCH | 결과와 마지막 투구가 맞지 않음. 삼진인데 세 번째 스트라이크가 아니거나, 볼넷인데 네 번째 볼이 아니거나, 타구 결과인데 마지막이 X가 아님. 사구·고의사구는 어느 카운트에서도 끝날 수 있음 |
| SPLIT_SAME | 결과 없는 타석 뒤에 같은 반이닝·같은 타자·같은 투수의 타석이 이어짐 (타석 분리 의심) |
| SPLIT_PCHANGE | 위와 같으나 투수가 다름 (투구 중 교체, 실제 사건이지만 카운트가 0-0으로 다시 시작) |
| HALF_END / OTHER_OPEN | 결과 없는 타석이 반이닝 끝 / 그 밖 (주자 아웃 등 실제 사건이 대부분) |
| DUP_CONSEC | 연속한 두 행의 구속·구종·호출·px·pz가 모두 같음 |
| DUP_TRAJ | 한 경기 안 궤적 계수 9개가 모두 같은 서로 다른 행 (유효 궤적만) |
| B 중심 d≤0.8 | VB `B`인데 존 정규화 거리 max(\|x\|,\|z\|) ≤ 0.8 (ABS 시즌 고위험 표시, 4.8절) |

규칙 수정 이력: 처음에는 `포BO`를 낫아웃 삼진으로 분류했다. 실제로는 마지막 투구가 0–1스트라이크의 X인 타구 아웃이라 타구 결과로 옮겼다(2024 END_MISMATCH 126→108). 또 TrackMan 규칙별 표가 투구 수가 다른 키를 빠뜨리던 버그를 고쳤다.

## 4. TrackMan 대조 (2019–2024)

### 4.1 매칭 방식과 한계

- **처음 방식(순서 연결, `pa_flow_audit.py`):** (경기, 이닝, 초/말, 타자) 키에서 VB와 TrackMan 투구 수가 같으면 순서대로 붙였다. 구속은 전체 중앙값만 봤다. `docs/tracking-data.md`가 요구하는 투구별 선수 ID·상태·구속 검증에 못 미친다. 수치는 비교용으로만 남긴다.
- **엄격 매칭(`pa_flow_strict.py`):** 검증 대상인 볼·스트라이크 카운트는 조건에서 뺐다. 대신 다음 조건을 모두 통과한 쌍만 쓴다.
  1. 경기: 같은 날짜 투수 ID 집합이 일치해야 한다(`build_trackman_id_crosswalk.map_games`).
  2. 선수: TrackMan 투수·타자 ID를 대응표로 VB ID로 옮길 수 있어야 한다. 대응표는 선수 단위(20구 이상, 양방향 90% 이상)다. 대응표를 만들 때 카운트가 맞는 투구를 썼지만, 투구 약 1%의 카운트 오류가 선수 대응을 바꾸지는 않는다.
  3. 구간: 반이닝 안에서 (투수, 타자)가 이어지는 투구 묶음을 양쪽 순서대로 맞춘다. VB의 타석 분리·중복은 구간 경계를 바꾸지 않는다.
  4. 투구: 구간 안에서 순서를 지키는 대응의 모든 쌍이 아웃 수가 같고, 개별 구속 차가 시즌 오프셋 ±2.0km/h 안이어야 한다.
     - 투구 수가 같으면 대응은 하나뿐이다. 한 쌍이라도 어기면 구간 전체를 버린다.
     - 투구 수가 다르면(차 3 이하) 가능한 대응을 모두 센다. 정확히 하나일 때만 받고, 여럿이면 '모호', 없으면 '대응 없음'으로 버린다.
- **호출 대조:** 매칭 투구 i의 TrackMan 다음 투구 i+1이 같은 TrackMan 타석이고 i+1도 매칭된 경우만 센다. 교차하는 것은 TrackMan 카운트 변화(볼 +1 / 스트라이크 +1 / 변화 없음)와 VB 호출이다.

## 5. ABS 시즌 ZA 입력 노출 (2024–2026)

## 6. 확인된 것과 가설

확인됨 (자료로 직접 보임)
- 김택연 타석: VB 9행 대 네이버 7구, 타석 분리, 중복·혼합 두 쌍, 볼카운트 오류(083-01부터 볼 1개 부족)
- 파서의 카운트 cap과 `V` 미집계, 검증의 흐름 오류 누락(코드)
- 엄격 매칭에서 VB 카운트와 TrackMan 카운트가 어긋나는 투구: 매칭 쌍의 0.81–1.10%
- 그 시작점은 대부분 VB `B`–TrackMan 스트라이크, 다음이 VB `V`
- 매칭된 `V`는 모두 TrackMan 스트라이크. VB 흐름도 `V`를 스트라이크로 셀 때 더 잘 성립한다
- 2024 존 중심 VB `B`는 판정 가능한 268구 모두 TrackMan과 충돌한다
- 행 과다형 오류가 있는 경기 목록(3.1절)
- 이 행들이 SBJ의 p_swing·p_zone 학습, 채점 분모, DV에 들어가는 경로(5.1절)

가설 (근거는 있으나 확정 아님)
- B–TrackMan 스트라이크 불일치의 대부분이 VB 오류라는 것. 개별 공으로 뒷받침되는 것은 22–28%다.
- 그 공들의 실제 행동(루킹/헛스윙) 비율. 존 안 비율로 거칠게 반반으로 추정했다.
- `V`의 실제 의미
- 매칭되지 않은 투구(24–40%)도 같은 비율이라는 것. 시즌 전체 규모 추정이 이 가정에 기대고 있다.
- 2025–2026에도 같은 비율의 호출 오류가 있다는 것(TrackMan 없음)
- 2025년 볼넷 흐름 불일치 증가(3절)의 원인
- 아웃 불일치(시즌당 약 1,000구)의 원인과 어느 쪽 기록 문제인지

## 7. 최소 수정안 (모두 별도 승인 사항, 이번에는 구현하지 않음)

1. **검증 경고 추가 (데이터 불변):** `validation`에 cap 없는 재계산 흐름 검사를 넣는다(K_CONT, BB_CONT, X_NONLAST, END_MISMATCH, SPLIT_SAME, DUP_CONSEC, DUP_TRAJ). 결과를 manifest에 경고로 남긴다. 공개 값이 바뀌지 않아 가장 먼저 할 수 있다.
2. **`V` 카운트 집계 (공개 값 변경):** `apply_non_terminal_pitch`에서 `V`를 2스트라이크 전까지 스트라이크로 센다. TrackMan과 VB 내부 흐름 두 근거가 같은 방향이다. `V` 행 자체를 스윙/테이크로 분류하는 것은 의미를 모르므로 하지 않는다.
3. **ZA 방어 (공개 값 변경):** 흐름 규칙에 걸린 타석과 ABS 시즌 존 중심 VB `B`를 채점에서 뺀다. 학습에서는 행을 지우지 않고 가중치 0으로 둔다.
4. **하지 않는 것:**
   - B를 T나 S로 자동 재분류하는 것(행동을 모름)
   - 위치가 불확실한 행을 `px`로 대체하는 것
   - 중복·혼합 쌍 중 한 행을 골라 지우는 것
5. **분석 코드:** TrackMan 대조는 `pa_flow_strict.py`의 엄격 매칭을 기준으로 한다. `pa_flow_audit.py`의 순서 연결 대조는 비교용으로만 둔다.

미해결: 네이버 표본 12건 대조(4.10절), 김택연 타석 두 쌍 중 실제 행, `V`의 의미, 아웃 불일치.
