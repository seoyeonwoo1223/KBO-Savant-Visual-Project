# GPT 토론용 지시: SBJ 위치 입력 결정

## 목표

SBJ(Strike Zone Judgment)의 위치 입력을 정한다. 결정할 것은 네 가지다.

1. 2024–2026 `p_zone`: 보고 `px/pz`(A)와 판정면 입력(B, za7.2) 중 무엇을 쓸지
2. 2022–2023 `p_zone`(심판 판정 시즌): `px/pz`를 유지할지
3. `p_swing`의 위치 입력: 현행(`px/pz` 상대 위치 + 구장 보정 HB/IVB)을 유지할지
4. 궤적이 무효인 행을 어떻게 처리할지

결론은 근거와 함께 권고안으로 낸다. 코드 변경, 공개 값 변경, PR 병합은 하지 않는다.

## 지금까지 확정된 사실

- **VB 좌표의 기준면**
  - `px`: 2019–2023은 플레이트 앞면(y=17/12 ft), 2024–2026은 중간면(y=8.5/12 ft)
  - `pz`: 모든 시즌 앞면
  - `px/pz`와 HB/IVB는 모두 VB 궤적 9계수에서 계산된 값이다. 서로 독립된 근거가 아니다.
  - 네이버 `ptsOptions`(`crossPlateX`, `crossPlateY`, `topSz`, `bottomSz`, 궤적 계수)도 대부분 VB와 같은 값이다(PR #31). 따라서 독립 검증이 아니다.
- **입력 구성**
  - `p_swing`: `x_relative`, `z_relative`(`px/pz` 기반), 카운트, 아웃, 주자 상태, 표시 구속, 릴리스 높이, 구장 보정 HB/IVB, 구종, 타석 방향, 구장
  - `p_zone`의 A: `x_relative`, `z_relative`, `sz_top`, `sz_bottom`
  - `p_zone`의 B(za7.2): `x_mid_relative`, `top_gap_cm`(중간·뒷면 z 중 큰 값 기준), `bottom_gap_cm`(작은 값 기준)
  - za7.3(`px` 대체, 커밋 `40d7bff1`)은 쓰지 않기로 했다. 병합하지 않는다.
- **공개 SBJ 상태**: 공개 SBJ는 현재 A다. B는 PR #28/#29에 있다. 병합 순서는 #29 → #28이고, 공개 값이 바뀌므로 승인이 필요하다.
- **2024 비교 결과(같은 공·폴드·모델)**
  - 로그손실: B 0.02686, A 0.04008. 차이의 신뢰구간이 0을 포함하지 않는다.
  - 개선은 존 경계에 몰려 있다. 경계에서 먼 공은 A가 약간 낫다.
  - 시드만 바꿔도 선수 `za_raw`가 평균 약 0.05, 최대 0.2–0.34점 흔들린다.
- **레이블 오염**
  - "VB 볼, TrackMan 카운트는 스트라이크"인 테이크 571구가 B 모델 손실의 54%였다.
  - 이 571구를 평가에서만 빼면 B 0.01232, A 0.02649다.
  - 원인은 VB가 번트 파울을 `B`로 기록한 것이다. 네이버 표본 42/42구와 13/13구에서 `W/번트파울`로 확인됐다.
- **번트 정정**
  - 2019–2024년 TrackMan 카운트 전이로 3,860구를 골라 `data/corrections/vb_bunt_foul_corrections.json`에 정리했다. 2024년 596구이고, 위 571구 중 568구가 포함된다.
  - 파서는 이 공들을 `W`로 바꾼다. 스윙도 테이크도 아니고, 카운트는 스트라이크 +1이다.
  - **아직 커밋된 curated에는 적용되지 않았다**(`scripts/apply_call_corrections.py` 실행 대기).
  - 2025–2026년은 TrackMan이 없어 정정되지 않았다. 네이버 `pitchResult=W`로 따로 찾아야 한다.
- **해석의 한계**: 평가 목표는 ABS 호출(2024+)이다. 따라서 "B가 호출을 더 잘 재현한다"는 뜻일 뿐, 물리 위치가 더 정확하다는 근거는 아니다. KBO 2024 ABS 규정은 좌우와 상하 판정에 서로 다른 플레이트 지점을 쓴다.

## 토론에서 다룰 질문

1. 번트 정정을 적용한 뒤에도 B의 우위가 유지되는가? 571구를 평가에서만 빼는 것과, 정정 레이블로 **재학습**하는 것은 다른 비교다.
2. 2025–2026년은 번트 파울이 남은 상태다. 이 시즌의 비교와 공개 값은 어떻게 다룰까?
   - 네이버 `W` 수집을 기다릴지
   - 정정 없이 입력 방식만 먼저 바꿀지
3. 경계에서 먼 공에서 A가 약간 나은 이유는 무엇인가? 혼합(경계 근처만 B)은 필요한가? 단순함을 우선할지도 함께 판단한다.
4. `p_swing`의 `z_relative`는 앞면 `pz`, `x_relative`는 2024+ 중간면 `px`로 평면이 섞여 있다. 타자의 스윙 결정을 설명하는 입력으로 이것이 문제가 되는가? 바꾼다면 어떤 실험으로 확인할까?
5. 궤적이 무효인 행: 적격 투구에서는 0구지만, 학습에서 빼는 규칙을 명시할지. `px` 대체는 하지 않는다.
6. 결정 기준: 로그손실·Brier 차이, 선수 순위 변화, 시드 잡음 대비 효과 크기를 어떤 임계로 볼지

## 권장 실험 순서 (읽기 전용, 결과는 `analysis/sbj_location/results/` 요약만)

1. 번트 정정표를 적용한 작업 사본에서 2024 `pzone_experiment.py`를 다시 돌린다. 같은 폴드·시드를 쓰고, A·B 로그손실과 차이의 신뢰구간을 낸다.
   - 원본 curated는 건드리지 않는다. 임시 루트를 쓰거나, 적용 스크립트를 사용자가 실행한 뒤에 돌린다.
2. 경계 거리 구간별 A−B 차이, 선수별 `za_raw` 변화, 시드 잡음 대비 비율을 낸다.
3. 2025–2026은 번트 오염을 표시한 상태로 같은 비교를 하고, 결과를 따로 보고한다.
