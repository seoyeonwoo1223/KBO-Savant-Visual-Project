# 2026 oWAR 포지션별 출전량 보정

## 기존 산식과 변경 근거

기존 생성기는 VB 타석에서 가장 많이 표시된 포지션 하나의 계수를 전체 PA/600에 곱했다. 이 방식은 포수·1루·DH 등 여러 역할로 출전한 선수를 한 포지션으로 처리하고 수비 출전량을 실제 이닝으로 측정하지 못한다.

기존 계수(C +10, 1B −8, 2B +3, 3B −1, SS +7, LF/RF −5, CF +3, DH −15)는 유지한다. 해당 KBO 시즌에 새로 추정하거나 공식 WAR 계수로 주장하지 않는다. 수비 계수는 144경기×9이닝=1296이닝당, DH 계수는 600타석당으로 적용한다.

`수비 보정 = Σ[포지션 계수 × 공식 해당 포지션 아웃 수 / 3888]`

`DH 보정 = −15 × DH 타석 / 600`

`oWAR = [기존 타격 추정 득점 + 도루 추정 득점 + 수비 보정 + DH 보정 + 20×PA/600] / runs_per_win`

수비 보정은 OAA 같은 수비 성과가 아니라 해당 포지션에 실제로 출전한 양에 대한 보정이다. DH 타석을 수비 포지션에 다시 배분하지 않는다. 공식 1/3·2/3이닝은 소수 .1/.2로 읽지 않고 정수 아웃 수로 저장한다.

## VB 원본 한계와 DH 불확실성

`20260401KTHH0`에서 장성우의 VB 포지션은 여러 타석에 `지포`로 동일하게 기록된다. 교체 정보에도 장성우의 DH→포수 전환 시점이 직접 노출되지 않는다. 복합 표시는 경기 동안의 포지션 목록으로, 해당 타석의 단일 수비 역할로 읽을 수 없다. VB만으로 정확한 포지션별 수비이닝·DH 전환 타석을 재구성하지 않는다.

VB가 `지`라고만 표시한 타석은 확인된 DH PA로 센다. `지포`, `지일`처럼 DH가 포함된 복합 표시는 네이버 문자중계의 타자 소개(`type=8`)에 붙은 `batterRecord.pos`로 재검증한다. 이닝 시작 문구의 포지션과 최종 라인업은 사용하지 않는다. 선수 ID·이름·이닝·초/말을 연결하고, 같은 선수의 해당 이닝 타석 수가 일치할 때 순서대로 대응한다. 첫 투구·타석 결과 전에 반복되는 같은 선수·같은 포지션의 소개는 한 타석으로 센다. 네이버 위치가 DH면 DH PA를 더하고 수비 위치면 DH에서 제외한다. 대타·대주 표기나 누락·불일치가 있으면 미확정 DH PA로 남긴다. 이 타석을 모두 DH로 처리한 경우와 모두 DH가 아니라고 처리한 경우가 가능한 보정 범위의 양 끝이다. 공식 수비이닝은 양 끝 모두 동일하게 적용한다. 두 oWAR 값이 0.01승 단위로 다르면 표에 범위를 표시하고 하한으로 정렬한다. 반올림 결과가 같으면 해당 숫자 하나를 표시하되 원본 산출물에는 미확정 타석 수와 보정 범위를 남긴다. 복합 타석을 절반으로 나누거나 임의의 시점을 만들지 않는다.

공식 수비 기록은 해당 시즌 현재 누적값이며 PBP 기준일과 다를 수 있다. 기존 공식 주루와 같은 시점 차이 한계를 화면에 명시한다. 전체 공식 수비 목록에 기록이 없는 선수는 수비 출전 0으로 처리할 수 있지만, 이름이 불일치하는 선수는 보정을 미확인으로 남긴다.

## 검증 예

- 포수 1296이닝·DH 0 PA: +10점.
- 포수 432이닝·1루 432이닝·DH 100 PA: 10/3−8/3−2.5점.
- DH 600 PA·수비 0이닝: −15점.
- 확인 DH 100 PA·미확정 DH 4 PA·수비 0이닝: −2.6~−2.5점.
- 같은 선수의 기본/확장 oWAR와 범위는 동일해야 한다.
